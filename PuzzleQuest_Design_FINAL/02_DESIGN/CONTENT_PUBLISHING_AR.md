# إضافة مراحل جديدة عبر لوحة Laravel دون تحديث تطبيق — تصميم فقط

**المعتمد:** الإطلاق خمس مراحل فعلية (1-1 إلى 1-5) في Green Valley؛ لا مراحل وهمية. Snow Land وDesert Ruins مغلقان بلا محتوى منشور.

**شاشات الإدارة القائمة:** ADM02 للعوالم/المراحل وADM03 لتفاصيل المرحلة؛ لا شاشة لاعب أو لعبة أو اقتصاد إضافي. مع ظهور كل مرحلة مستقبلية في الشاشات 03/04/05/06 الموجودة اعتمادًا على كتالوج API، وليس على مصفوفة ثابتة داخل التطبيق.

**سير العمل التصميمي:** Draft → Upload master + thumbnail + selected geometry package (manifest, pieces, masks) → Validate bytes/types/paths/image dimensions/anchors/pieces/seams/checksum/level order/timing → Ready → Publish (atomic revision) → live catalog refresh. Preview وValidation نتائج التصميم وليست تطبيقًا خادمًا عاملًا. يحتفظ النظام بمراحل/صور المحاولات القائمة عند تغيير النسخة، ولا يغيّر منشورًا نشطًا باستبدال بايتاته مباشرة.

**قواعد صارمة:** ID مستقر، ترتيب داخل العالم، عالم موجود ومعروف، فتح السابقة بنجمة واحدة على الأقل، world next unlock only if previous world complete AND next world content published/ready. صورة/master وكل القطع المطلوبة للفئة المختارة جاهزة. صيغة Manifest وإحداثياتها متوافقة مع عميل Flutter/Flame المنشور (16/36/64/100 فقط). لا تنزيل ملف غير موثق أو بيانات من مصدر مفتوح، ولا عرض مرحلة غير متحقق منها. كل كتالوج وصورة منشوران بنسخة immutable وSHA256. عند تغيير schema/لوحة/نظام اللعب، يلزم إصدار تطبيق وليس مجرد بيانات.

**قواعد الاعتماد:** لا يمكن Publishing فعلي قبل اعتماد Q05-T للمراحل الجديدة، واختبار الجهاز عند 100 قطعة وتوافق لوحة المساحات. القائمة عند الإطلاق 5 مراحل فقط. أزمنة النجوم/فشل العداد لا تُستنتج من الصورة.

**الـBackend عند التنفيذ:** صلاحية تحرير/نشر منفصلة، سجل تدقيق، حفظ Draft عند فشل رفع/Validation، عدم نشر محتوى غير جاهز، إلغاء/إعادة محاولة آمن، منع نشر متزامن، ومعالجة ملفات ضخمة دون تجميد لوحة الإدارة. تسلسل العمليات والعقود الدقيقة في `CONTENT_PUBLISHING_CONTRACT.json`.

لا يوجد في هذه الحزمة Laravel API أو تنفيذ Upload أو CDN أو اختبار جهاز.
